# M42 device handoff

Status: measurements outstanding. Owner approval is already recorded; this asks for observations, not another approval.
Use synthetic or your own permitted material, a test learner and the exact release candidate. Do not submit private learner files in bug reports.

Required OS coverage (PLT-01): Windows 10 22H2 and Windows 11 x64, including a non-AVX2 baseline CPU; macOS 13+ on Apple Silicon; Ubuntu 22.04+ and Debian 12 x64. Linux becomes required at S3. Intel macOS is unsupported; Windows Arm is optional and is not a release blocker. Across these machines cover the benchmark-selected content-only, low, mid and high classes; each local model candidate needs its own safety/grounding run. Do not force a class the hardware cannot run.

Record OS/version, CPU/features, RAM, GPU/driver, free disk, selected class, app/installer SHA-256, model/OCR/ASR/TTS pack IDs and hashes, start/end time, tester and pass/fail per check. For failures give the step, expected/observed result, redacted logs and a screenshot if useful. Leave untested fields null in `m42-device-report.example.json`.

| ID | Device action | Expected evidence |
| --- | --- | --- |
| D01 Install and signature | Disconnect internet. Install the packaged USB candidate as a normal user and launch. Windows: verify Authenticode and timestamp for app, sidecars, EXEs/DLLs; test with Windows Security enabled. macOS: inspect nested signatures, hardened runtime, notarisation and stapled ticket; run Gatekeeper assessment offline. Linux: verify detached AppImage signature or signed apt metadata and package digest. | No network required for installation; no unsigned executable/library, signing warning or quarantine/antivirus failure. For a minor test both Study-specific guardian consent absent and present. | No late publication, upload after withdrawal, cross-profile text, duplicate aid or charge. The release operator must also exercise the **deployed** gateway: paid project/retention verification, body-log and disk inspection, swap/core-dump restrictions, sandbox operation, process kill/restart, idle expiry and receipt reconciliation. These are server checks, not something you must reproduce on your laptop.

What needs your help: access to the listed Windows/macOS/Linux machines and NVDA/VoiceOver, with the installed model/voice packs, plus the observations above. The automated code, codec, browser and live-provider checks can be run here. Signing credentials, real production configuration and an independently reviewed held-out corpus must come from their existing custodians; no private key should be sent in chat.
