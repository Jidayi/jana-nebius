# M42 operations

The Nebius demo uses `study_model = "primary/strong-model"` for Study generation and verification and
`study_vision_model = "primary/vision-model"` for scanned-page transcription. The concrete Token Factory routes
and prices are in `cloud_gateway/defaults.toml`; deployment limits are in `deploy/nebius-dev.toml`. Provider keys
stay in the gateway's secret source. The development host enables Study for the demo; production release evidence
remains a separate requirement. Live verification uses synthetic material.

Study uploads, source bytes, transcript chunks, prompts and results stay in bounded gateway memory. Upload buffers
expire after 15 minutes of inactivity; explicit deletion cancels in-flight work and clears bytes. Extraction/media
workers have no network permission and receive source bytes over stdin. The server-only PyAV dependency is not
bundled into the desktop. Recording segments contain at most 60 seconds of mono 16 kHz PCM; the total is capped at
120 minutes/100 MB. Non-English or uncertain segments are withheld and require learner review/correction.

`study_extract_page_usd` and `study_extract_minute_usd` are configurable engineering proposals. Their default
0.0001 USD unit rates are not deployment cost measurements. Qualify them against the chosen deployment's compute
bill before public billing. Token charges use the provider's actual input/output/cached usage, with one durable
settlement per attempt. The returned usage receipt includes both transcription and extraction costs. Known failed
calls settle their actual usage; an unknown provider outcome retains its reservation rather than being replayed.

## Bounded draft correction

The gateway can generate one revised draft after a fully observed support rejection. It does this only when
the verifier explicitly reports a repairable drafting mistake and that the original material is safe,
consistent and sufficient. Missing answers, contradictions, unsafe material, malformed replies and uncertain
provider outcomes do not qualify. The revised draft repeats canonical schema, exact citation and independent
support/safety checks; a second rejection is final. A source symbol without a definition keeps its literal
notation in accompanying claims and flashcard fronts/backs.

Draft citation IDs are enumerated from the current frozen passages in the provider schema; invented or mixed
references still fail gateway binding. For source-reporting chat questions, generation and verification distinguish
faithfully reporting a conditional statement from applying it to a particular example. Conditions must remain
explicit; a missing premise still prevents an answer about that example's actual value. This does not change
canonical client contracts, permit outside physics assumptions or relax the support check.

There are at most two generation calls and two verification calls within one 180-second processing deadline.
Admission reserves the conservative upper bound for all four calls; actual known usage settles once in the
same attempt receipt. Reviewer feedback stays in memory and is treated as untrusted data. This is correction
of a known rejected draft, not replay of an uncertain request. Deletion/cancellation still prevents publication.

## Resolving an uncertain send

Obtain the provider's usage/invoice record independently. Keep that record in the restricted billing evidence
system and compute its SHA-256 digest. Never put source material, keys or the invoice itself in gateway storage.

Preview a settlement against an existing gateway storage directory:

```sh
python -m cloud_gateway.study_reconcile --storage-dir /srv/jana/gateway \
  --receipt RECEIPT_SHA256 --cost-usd ACTUAL_USD --evidence-sha256 EVIDENCE_SHA256
```

After inspecting the preview, add `--apply`. The command atomically releases the held upper bound, records actual
cost in the original subscription month, and stores only opaque receipt/evidence digests and accounting values.
An identical replay is a no-op; conflicting evidence/cost fails. It makes no provider call. Reconciled costs count
conservatively against the account's current daily admission limit without preserving a link to a rotating device
hash. Completed audit metadata is purged within the existing retention window. Uncertain holds require operator
resolution; do not manually delete them to make quota appear available.

## Release evidence

Owner approval: `scripts/governance/m42-owner-approval.json`. That attestation does not create a content-key
signature. A production release must carry its approved signed `dpia_list` including the `study_materials` feature
at `s3_launch`, the approved provider-retention evidence and configured hosts/pins. Preserve all PDFium licence
texts and the exact native wheel audit; each desktop wheel has a separate hash audit, while the deployment's PyAV/FFmpeg image still requires
its own native provenance. Keep corresponding FFmpeg sources/build information with distributed gateway images.
